## 1. The custody chain AS IT EXISTS (recorded mode)

### What recorded-mode evidence honestly asserts

Stated precisely, a recorded-mode report asserts:

> "A byte sequence that (a) internally hash-verifies — every response's `result` matches its embedded `rawResponseSha256` and every envelope matches its embedded `envelopeSha256` — and (b) was reviewed into this repository as an authored reference scenario, was mechanically evaluated under a manifest whose content hash was approved by the deployment trust policy, producing these verdicts; the evaluation is bit-for-bit reproducible from those bytes."

It does **not** assert that any provider ever returned those bytes, that any chain was ever in that state, or that any `capturedAt` is a real capture time. The repo says this itself, three ways: `data/recordings/README.md:3-7` OBSERVED ("These are **not** live capture… illustrative reference values"), the payload's baked-in limitation OBSERVED at `lib/aegis/surfaces/engine.ts:251` (`recorded_inputs`: "Evaluated from reviewed recorded fixtures; not live production telemetry"), and provenanceClass `reference_scenario` in the deployment config. The fixture is even *visibly* synthetic: parent hashes are sentinel values `0x1111…`, `0x2222…`, `0x3333…`, `0x4444…` OBSERVED at `data/recordings/reference-eth-op-heads.json:14,48,82,99`. This candor is a strength; guard it.

### The chain, link by link

**Link 1 — Origin (authoring/review → repo).**
Binding mechanism: human review + a git commit (`4a2fded`, 2026-07-22, "sealed reference bundle" — OBSERVED via `git log --follow`). Nothing mechanical binds bundle content to a reviewer act: commits are **unsigned** (OBSERVED: `git log --format=%G?` → `N` across recent history), and no reviewer attestation object exists. Forgery cost: whatever it costs to land a commit — for the repo owner, zero; for an outsider, push access. Detectability: git history diff on the two remotes (github.com/kaseLunt/aegis + a sites remote, OBSERVED `git remote -v`), i.e., detectable only by someone who thinks to look, with no monitor. ANTI-CANON adjacency: this link is one step from trust-me attestation — its saving grace is that the *claim scope is honestly narrow* (reference scenario, not observation).

**Link 2 — Transport.**
Vacuously absent: no bytes ever crossed a network for these fixtures. The `providerId: "alchemy"` / `administrativeDomain: "Alchemy Insights, Inc."` strings (OBSERVED `lib/aegis/chain/providers.ts:22-39`) bind to nothing outside the repo. The one real control at this link is that `sourceMode: "recorded"` is adapter-declared, never caller-labelable (OBSERVED `lib/aegis/chain/adapter.ts:196-210`, Codex W4 finding 8) — a fixture cannot claim to be live *through the pipeline*. Forgery cost of the provider labels themselves: editing a string (see Link 3 for why that's partially caught).

**Link 3 — Storage (bytes at rest → bytes at load).**
Binding mechanism, OBSERVED `lib/aegis/chain/adapter.ts:102-165` (`loadRecordingBytes`): strict UTF-8; duplicate-JSON-key scan (R-003 closed — `lib/aegis/report/canonical.ts:173-238`); per-response `rawResponseSha256` = sha256(JCS(result)); `envelopeSha256` over providerId/chainId/method/params/capturedAt/rawResponseSha256/result (the hash cannot cover itself, `adapter.ts:149-152`); duplicate lookup-key rejection; deep-freeze + process-local WeakSet brand. What `integrity_mismatch` catches: corruption, naive value edits, and **relabeling** — copying provider A's response under provider B's name fails because `envelopeSha256` binds `providerId` (the Codex W3 P1#3 closure).

What it does not catch, and this is the load-bearing sentence: **the bundle authenticates itself against itself**. An editor who recomputes both hashes after tampering produces a bundle the loader fully accepts. Forgery cost of the storage link in isolation: two SHA-256 computations over JCS bytes — minutes, scriptable. The only whole-bundle digest binding anywhere today lives **outside the evidence pipeline**, in the roadmap receipt chain (`EV-W3-R5` `input_fingerprint` at `tested_commit`, since W3's deliverables include the bundle — OBSERVED `roadmap/work/W3-finalized-blocks-quorum.md:23`), which a report verifier can neither reach nor even name: **the payload carries no `recordingId` and no bundle digest** (OBSERVED `engine.ts:149-159` — evidence refs carry providerId/method/boundary/rawResultHash/capturedAt only). Report→bundle traceability today is *by reproduction search*, not by reference. This is exactly R-b4e2e152 §1, open by design.

**Link 4 — Evaluation.**
Binding mechanism: brand re-earned from raw bytes in-process each run (OBSERVED `engine.ts:108-112`, `adapter.ts:174-176`; INS-a6fc2796 addendum 3 CANON — brands are process-local, so a "verified" object cannot be shipped in); quorum requires ≥2 *distinct administrative domains*, aliases can't self-corroborate (OBSERVED `lib/aegis/chain/quorum.ts:136-138`); observations comparable only at one pinned block, block-hash conflict → `conflict`, raw-hash conflict → `conflict`, missing → `unknown`, never a value (`quorum.ts:91-148`); identity reads are EIP-1898 block-hash-pinned with `requireCanonical: true` (`adapter.ts:229-268`); targets extracted only from the manifest whose recomputed content hash IS `policyTrust.manifestHash` — **risk §3 is CLOSED by W5 S1** (OBSERVED `engine.ts:199-210`, `roadmap/work/W5-one-engine-four-surfaces.md:67-70,143-155`). Forgery cost for a *caller* of the pipeline: high — thirteen Codex passes closed hand-built-observation, value↔hash, TOCTOU, and coercion paths (CANON: EV-W4). Forgery cost for a *fixture author*: near zero, and the evaluator correctly does not claim otherwise (R-b4e2e152 Bounding, OBSERVED).

One fact a reviewer will weaponize if unnamed: in the shipped bundle, the chain-1 "agreement" between alchemy and quicknode is **one authored result duplicated** — both responses carry the identical `rawResponseSha256:f00e2e…` (OBSERVED `reference-eth-op-heads.json:18,35`; envelopes differ only by providerId). The reference fixture is, structurally, the exact forged-bundle shape the risk describes — legitimate solely because the provenance class and limitation say so. Recorded-mode "quorum agreement" is therefore a **mechanism demonstration**, never corroboration, and no surface may phrase it otherwise (W5 acceptance line, OBSERVED `W5:85-87`).

**Link 5 — Report.**
Binding mechanism: strict validation (byte lengths, sha256 identifiers, enums) → normalization → RFC 8785 JCS → `reportHash` (OBSERVED `lib/aegis/report/canonical.ts:505-660`); payload deep-frozen so a transport cannot show one value while the hash covers another (`engine.ts:280-285`); delivery metadata excluded from identity. Forgery cost: producing a different payload under the same hash = SHA-256 collision. Producing a *dishonest payload under a fresh hash* costs nothing — by design, the defense is reproduction: re-run the canonical engine on the stored inputs and compare hashes (Reproducible-Builds doctrine CANON: identity checkable by re-derivation, not trust). Residual: `evaluationTime` is an injected input, not an attested time (deterministic by design, `W5:306-308`) — a recorded-mode report's timestamps are *claims within the reviewed scenario*, consistent with the honest boundary but worth naming (ANTI-CANON: timestamp-free claims cannot expire, therefore cannot be honest — recorded mode escapes this only because it doesn't claim live time at all). Minor: head-evidence `capturedAt` falls back to the bundle-level timestamp (`engine.ts:118-130,158`; INS-84853447 CANON) — surfaces must not imply per-call head timestamps.

### Weakest link, named

**The Origin↔Storage seam: the bundle self-authenticates, and neither the report artifact nor any in-pipeline mechanism binds bundle bytes to the review act that made them trustworthy.** Cost to forge the storage link: recompute two hashes. Cost to make the forgery *count*: land it in the repo unnoticed — an unsigned-commit, no-monitor, two-remote git history is the entire chain of custody for that step. Every downstream link is strong precisely because it verifies against material this link supplies.

## 2. §1 designs — bundle-digest anchoring (post-capture tampering detectable)

**Option A — Normalized bundle content-hash + deployment-approved digest set (RECOMMENDED, rank 1).**
Define `bundleContentHash` = sha256 over JCS of the bundle with responses sorted by their canonical lookup key and the digest field itself excluded — the exact excluded-field pattern already proven at `manifestContentHash` (OBSERVED `lib/aegis/manifest/trust.ts:95-118`). `loadRecordingBytes` computes and returns it; the engine threads it into every evidence ref (`recordingBundleDigest`) and the payload; the deployment trust policy gains `approvedRecordingDigests`, an exact mirror of W2's `approvedHashes` (`trust.ts:78-88`). An unapproved bundle degrades verdicts to `unknown` with a typed reason — the untrusted-manifest pattern, reused.
*Defeats:* post-review tampering (recomputing per-response hashes now moves the bundle digest off the approved set); relabeled-copy *bundles* (a doctored second bundle is a different digest, closing the risk-§1 sentence verbatim); and the report→bundle traceability gap — `aegis reproduce sha256:<hash>` (W5 S4) gets its input reference for free.
*Knowingly does not defeat:* a dishonest fixture approved at review time (garbage honestly anchored is still garbage — same trust class as W2's curated list, CANON per R-b4e2e152 Bounding); an owner who edits bundle and approved set in one commit (detectable in git history, not prevented — CT doctrine CANON: "detectable" is the property bought, distinct from "prevented"). Cost: one slice; two existing house patterns reused; no new trust class introduced.

**Option B — Review/capture attestation + append-only journal (rank 2; the P3/live-mode strengthening).**
At sealing time, sign the `bundleContentHash` with an identity of documented custody (Sigstore keyless with the owner's OIDC identity, or a repo-documented SSH signing key) and append `{bundleDigest, sealedAt, sealerIdentity}` to an append-only journal — a Rekor entry, an OpenTimestamps anchor, or minimally a git ref that only fast-forwards, mirrored to both remotes.
*Defeats:* silent history rewrite even by the owner (journal fork detectable by any third party — anti-repudiation, Sigstore/CT pattern CANON); backdating (independent timestamp); "which bytes were actually sealed" disputes years later without access to the repo's git history.
*Knowingly does not defeat:* a dishonest sealer at sealing time (in-toto CANON: a step attestation is only as good as the step); and it adds an identity-custody story that must itself be documented or it becomes trust-me attestation (ANTI-CANON: signature by a key of unexplained custody). For today's *authored* fixtures there is no capture time — the honest form is review-time sealing; the capture-time form activates with the WR3 probe pipeline.

**Option C — Digest register + doctor teeth (rank 3; land immediately alongside A).**
A committed `data/recordings/REGISTER` mapping filename → bundleContentHash, plus a test recomputing it and a doctor rule failing on drift. Weakest of the three (the report still can't cite it; an editor can update register and bundle together) but it converts silent drift into a red gate today and is an hour of work. This is the "teeth habit" artifact (CANON: RULES §13-20) that should accompany Option A's landing regardless.

## 3. §2 designs — live endpoint/client-identity binding

Ranked by claim strength per unit cost. The decisive observation first: per the WR3 matrix, **no surveyed provider declares signed JSON-RPC responses** (OBSERVED: no such capability appears in any cell or provenance row of `roadmap/research/WR3/provider-matrix.md`) — so the strongest *available* bindings are the ones Aegis builds unilaterally.

**Rank 1 — Verifiable-response acquisition: re-derive, don't attest (unilateral; INFERRED design, grounded in existing machinery).**
Ethereum data is partially self-authenticating: a block header hashes to its own identity, so every `eth_getBlockByNumber` response can be verified by recomputing keccak(RLP(header)) against the pinned hash — and Aegis already pins by block hash with `requireCanonical: true` (OBSERVED `adapter.ts:229-268`). `eth_getStorageAt` upgrades to `eth_getProof`: a Merkle-Patricia proof against the pinned header's `stateRoot` converts "provider X said slot=V" into "slot=V under stateRoot R of block H" — *the provider drops out of the integrity claim entirely*; forgery cost becomes breaking keccak/the state trie. Residual honestly named: `eth_call` results have no proof object — arbitrary call output requires re-execution to verify (local EVM over proved state, or the matrix-§5 cross-check discipline: simulation output corroborated against a quorum member's raw reads). This is the single largest claim-strength upgrade available, it needs zero provider cooperation, and it converts provider trust from *integrity* to mere *liveness/censorship* for covered reads. (Reproducible-Builds voice CANON: identity checkable by re-derivation, not trust.)

**Rank 2 — Duplicate-fetch cross-provider corroboration (EXISTS; the quorum layer's contribution).**
Already built and correctly shaped: ≥2 distinct administrative domains at one pinned block, raw hashes compared, disagreement → `conflict`, insufficiency → `unknown` (OBSERVED `quorum.ts:64-149`). Live forgery cost: simultaneously compromise or coerce two administratively independent operators at the same pinned block — moderate-to-high, and the WR3 §4 do-not-pair analysis (DIN federation, aggregator opacity, shared-cloud) is what keeps that cost real rather than nominal. The live gap it inherits: `administrativeDomain` is a reviewed *config string*; the request to "quicknode" must actually reach QuickNode. That is what §6.7's probes close empirically — `web3_clientVersion` fingerprinting over days, DNS/ASN/TLS-chain mapping, error-shape fingerprinting (OBSERVED matrix `§6.7`) — and those probe results must be **recorded as evidence with raw hashes**, not run once and remembered. Limitation honestly named: corroboration is evaluation-time; a skeptic years later verifies "they agreed" only via the recorded raw hashes of both legs, which is where Rank 3 compounds.

**Rank 3 — TLS-session-derived capture evidence + transparency-style capture journaling (unilateral; land together).**
Extend the response envelope with `endpointIdentity` — hostname, resolved IP, TLS version, leaf-cert SPKI sha256, cert validity window — hashed under `envelopeSha256` like every other provenance field, and append every capture event `{bundleDigest, endpointIdentity, capturedAt, requestKey}` to the §1-Option-B journal. Be exact about what this is: TLS 1.3 session data is **not third-party-verifiable** — no transferable signature covers application data — so this is first-party attestation whose forgery cost is raised from "edit a string" to "control the capture host, or DNS/CA, at capture time." The leaf cert's CT-log presence (RFC 9162 CANON) independently proves the *certificate* is real, not that the bytes crossed it. The journal adds the property attestation alone lacks: silent re-capture-until-favorable becomes visible (every capture is logged, so the discard pattern is public), and post-hoc envelope rewriting forks the journal. Named upgrade path if transferability is ever required: TLSNotary-class MPC transcripts — heavy, experimental, priced accordingly. ANTI-CANON check: without the journal, TLS-derived fields alone are "the tool said so" — do not ship Rank 3's envelope fields without its journal.

**Rank 4 — Provider-signed responses (requires provider cooperation; unavailable today).**
Where a provider signs `{request, response, blockHash, timestamp}` under a published, rotated key, the response becomes offline-verifiable years later; forgery cost = provider signing-key compromise. No surveyed provider offers it (OBSERVED, matrix-wide absence); keep it as a standing ask in provider relationships and as the evaluation criterion if institutional pairs (Blockdaemon/Tenderly, matrix §5) are ever contracted — a contract is the one lever that could create this capability.

Cooperation split: Ranks 1-3 are Aegis-unilateral; Rank 4 is cooperation-only.

## 4. The migration honesty rule (provenance-class boundary)

**Rule: live mode strengthens by adding distinguishable provenance, never by reinterpreting stored provenance.** Concretely:

1. **Classes are immutable facts of the artifact.** A recorded-mode report's `provenanceClass: reference_scenario` / `sourceMode: recorded` and its reportHash are frozen; new verification code must re-derive the identical hash and the identical (weaker) claim from old inputs. No code path may re-emit an old bundle's evidence under a stronger class. The enum machinery for this already exists and is strict (OBSERVED `canonical.ts:424-435,492-493`; adapter-declared sourceMode `adapter.ts:209`).
2. **Absence of an anchor is a class, not a default.** Old bundles lack `bundleContentHash`-approval and `endpointIdentity`; the loader must surface "unanchored recorded" as a typed state — never default-fill, never silently accept an old envelope shape where a new one is expected (the fail-closed house idiom, CANON).
3. **Quorum must not mix classes silently.** `ProviderObservation.sourceMode` is currently ignored by quorum evaluation (OBSERVED `quorum.ts:29-31`). Before live adapters land, a mixed-sourceMode observation set must be a typed refusal or a surfaced reason code — a live leg "corroborating" a recorded leg is not agreement between independent observations, and today nothing would stop it structurally. **This is a concrete pre-live work item; flag it into R-b4e2e152 §2's closure scope.**
4. **Receipts attest new claims, they do not upgrade old ones.** The house supersession style already models this (OBSERVED EV-W4 → EV-W4-R3: `contract_fingerprint` byte-identical when the claim is unchanged, only `input_fingerprint` moves). Live-mode EV receipts must carry a *new* contract fingerprint — a different claim — never supersede a recorded-mode receipt as if re-attesting it.
5. **Language discipline is mechanical.** The trust-language lint (W5 acceptance, `W5:106-107`) is the enforcement surface: `recorded_inputs` text verbatim, no "live"/"verified" tokens on recorded surfaces — extend it to any new surface before that surface ships.

## 5. Verdict

**CUSTODY-SOUND — for the claims recorded-mode artifacts actually make; BROKEN AT the Origin↔Storage anchor for any claim one notch stronger.** Every assertion shipped today is honestly bounded: the fixtures are labeled authored (`reference_scenario` + `recorded_inputs` + sentinel parent hashes), the evaluator's caller-forgery surface is closed thirteen passes deep, risk §3 is closed at W5 S1 (`engine.ts:199-210`), and the open gap is filed, bounded, and owner-surfaced (R-b4e2e152). The chain does not overclaim — but its weakest link is real: the bundle self-authenticates (forgery = recompute two hashes), the binding to review is an unsigned git history with no monitor, and the report artifact cannot name the bundle it came from.

**Minimal P2 upgrade of the weakest link:** §1 Option A + Option C in one slice — `bundleContentHash` via the `manifestContentHash` excluded-field/normalization pattern, threaded into evidence refs and payload, `approvedRecordingDigests` mirroring W2's trust block with untrusted-recording → `unknown`, plus the digest register + doctor rule + negative test as the teeth artifact. This converts "edit + recompute two hashes" into "also alter deployment trust config in a scope-gated, receipt-fingerprinted repo," gives `aegis reproduce` its input reference, and introduces zero new trust classes. §1 Option B (signed sealing + append-only journal) and the §4 item 3 quorum sourceMode guard are the two pre-live prerequisites to schedule when R-b4e2e152 §2 opens; §2 Rank 1 (header re-hash + `eth_getProof`) should be designed into the live adapter contract from its first line, because it is the only option that removes the provider from the integrity claim instead of merely raising the cost of lying about it.
